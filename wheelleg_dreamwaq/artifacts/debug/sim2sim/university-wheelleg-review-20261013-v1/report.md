# 高校轮腿控制与平滑方案核对（2026-10-13）

本轮目的：回应“能否参考其他高校的轮腿前进／后退和神经网络平滑做法”，为后续网络／训练设计提供源码依据。这里只保存公开参考源码、论文页面和研究记录；不启动训练，不修改生产、训练、奖励、观测、动作、USD或MuJoCo参数。

## 结论

可以参考。最贴近的是南方科技大学 CLEAR Lab 的双轮腿 Wheel-Legged-Gym；ETH 的轮腿论文提供了明确的腿部平滑定义；香港科技大学（广州）FLORES 的公开配置和部署入口提供了另一组交叉证据。

这次没有找到足以证明“换一种神经网络就能消除我们抖动”的依据。已核对的南科大训练入口采用历史编码器、MLP Actor 和普通 PPO，其平滑主要在奖励中实现。ETH 的教师／学生网络和执行器模型各有职责，不能把历史网络或执行器网络等同于专门的平滑网络。

参考源码也没有支持给我们的旧策略增加部署期目标低通作为最终方案。之前的 debug 低通结果保留为诊断证据，用户的视觉验收未通过，且用户选择从网络／训练侧处理。

## ETH：同时看目标变化和实际腿运动

[原论文与补充材料](https://arxiv.org/html/2405.01792v1)，Learning Robust Autonomous Navigation and Locomotion for Wheeled-Legged Robots。

式(20)用12个腿关节的速度平方与加速度平方；式(21)用腿目标角的一阶和二阶变化平方。低层输出腿位置和轮速。论文中的5Hz低通出现在统计分析的状态测量处理中，不能当作已证明使用了部署期动作低通。Beta有界分布用于高层导航命令，也不能说成16维底层Actor都用Beta。执行器网络用于模拟实际电机响应，不是过滤Actor输出。

这个项目支持参考“实际腿运动＋腿目标变化”的训练定义，未给出本项目适用的ROGER阈值。四轮平地可静态支撑，其腿姿态要求不能直接用于双轮平衡。

另核对[ETH／加拿大合作的Ascento楼梯论文](https://arxiv.org/html/2402.06143v1)：其 articulated joints 用位置目标，wheels用速度目标；它是位置到达任务，不是我们当前速度任务的直接配方。论文提到关节加速度等整形项，但没有完整列出双轮平台平滑项，不能据此编造具体权重。接触滑动平均和训练观测延迟也不能称为动作滤波。

[论文v2](https://arxiv.org/html/2507.22345v2)；[作者官方仓库](https://github.com/ZhichengSong6/FLORES)。
固定提交814db438b70793f1115c491553d7cb39eaf6b74d，2026-05-22。

公开code/HIM_FLORES/mdog_config.py:100–108允许正负前进命令；:130–146包含速度跟踪、stand_still、dof_error、dof_acc、action_rate、smoothness。完整计算函数依赖外部legged_gym，当前公开仓库没有这些函数，因而公式的依据分别注明为论文而不是配置文件。

部署code/Mdog/controllers/rl_quadruped_controller/src/FSM/StateRL.cpp:347–398显示：网络推理→动作裁剪／缩放→关节位置／轮速目标→PD与力矩保护；这个入口未见目标时间低通。仓库有LowPassFilter.cpp，单凭文件存在不能认定它过滤RL动作。此结论不覆盖未核对的电机固件。

论文宣称4kHz驱动通信有助于稳定时序，策略仍是50Hz；不能把通信频率说成神经网络频率。论文与公开配置的观测尺寸也不完全一致；本轮不选其中之一移植，避免凭示意图构造训练契约。

## 前进／后退如何与phi0、pitch联系

已读速度任务把正负速度命令作为网络输入，网络同时选择腿与轮的动作；没有从正负命令到固定pitch或phi0的通用映射。

南科大VMC确实直接让网络选择虚拟腿摆角，物理意义与我们关心的phi0接近，但坐标零点和符号不同。它仍然同时选择轮速，并不等于只靠摆角驱动前后运动。

对本项目的推断：可以研究虚拟腿摆角／腿长作为动作表达是否减少不合适的两电机配合；不能仅凭观察到机身pitch变化就判断前后控制不正确，也不能在现有checkpoint后把关节动作直接改解读成phi0／腿长。这样的动作变更需要训练契约一致的新实验，当前不实施。

## 对当前工程的具体启发

当前生产rewards.py:61–74已有实际腿速度、全关节加速度、六维一阶／二阶执行动作代价。它不是完全缺少平滑项。差别在覆盖范围和实际贡献，尤其此前记录显示轮动作可占绝大多数总action_smooth，而饱和侧腿目标静止仍不保证实际腿不动。

建议后续设计以这些已核对做法为基线：
- 给腿目标变化和轮目标变化独立指标、独立尺度。六维总指标仍可保留用于兼容；先统计各组贡献，未来若改训练定义再明确写入架构。
- 同时验收实际两腿运动与目标变化，防止“目标恒定、机械仍抖”被当作成功。角加速度值需要保持采样步长和统计方式一致。
- 结合我们已有raw输出深越界证据，处理饱和行为。单纯再放大六维平滑权重没有证据能解决它。
- 继续保留速度跟踪、停车、换向、扰动平衡的联合验收，不用“腿完全不动”替代目标。
- VMC动作表达是第二种可研究方向，修改范围显著大于分组代价，需保留两平台一致的动作映射与安全边界。

如果坚持直接在网络优化目标上添加平滑约束，[波士顿大学CAPS](https://ai.bu.edu/caps/)是明确的参考：训练期约束相邻状态与相近状态上的策略输出。它的实机例子是四旋翼，本轮没有找到它已用于上述轮腿仓库的证据；不应包装成高校轮腿已经验证的补丁。上一份network-side-direction.md中的CAPS仅是候选，此次轮腿参考补充了更贴近的奖励覆盖与动作表达证据。
