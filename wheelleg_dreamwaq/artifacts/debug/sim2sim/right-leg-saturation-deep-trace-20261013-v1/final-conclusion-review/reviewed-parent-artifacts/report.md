# 轮腿抖动与速度跟踪：无训练诊断结论

日期：2026-10-13。范围：原 PhysicsV5 MuJoCo、已有 checkpoint、debug 脚本。正式架构仍为 v0.28，本报告不是架构变更或生产验收。未启动训练、未启动 Isaac 诊断，未修改训练代码、USD/XML、奖励、动作合同或正式 MuJoCo 控制器。211 个受保护文件与本轮之前的哈希一致。

## 结论与推荐

已找到一个**同一旧策略下明显减轻实际腿抖动、同时保留可用速度跟踪的 MuJoCo 候选方案**。它由“腿/轮分开控制目标变化速度”和“持续停车时的小幅慢纠偏”组成。可以先用此方案做视觉确认，无需为了验证这个候选先开新训练。

尚未实现“完全不震荡且原地不动”：腿仍有小幅周期运动，左右虚拟腿姿态仍不对称，停车仍有小范围往返。现有证据不能证明旧网络本身学好了，也不能保证 Isaac、实机、滑移和复杂地形上的效果。候选只安装在 debug 实验中，生产运行入口仍保持原行为。

不建议下一步继续盲目加大六维 action_smooth 或旧加速度预算的共同权重。已有结果表明问题含有单侧动作深饱和和高频闭环耦合，单个总惩罚的数值并不能代表左腿实际抖动。

## 诊断追到了哪里

### 1. 不是简单的右腿电机映射错误

机械审计按具名关节/actuator 比较，canonical actuator ID 为 [0,1,3,2,4,5]，正确处理了 XML 声明次序不同的问题。四个主动腿关节的 sign 一致，右轮使用现有正确的反向 sign。

101×101 可执行目标网格下，左右 planar FK 都有效，同目标轮轴向量最大差约 3.74e-7 m。原 reset 无接触时，左右反射后的六电机单位力矩响应矩阵相对差约 0.0119%。模型存在少量几何和质量不对称；这些结果只能排除已检查范围内的大映射/响应问题，不能证明全接触状态或两引擎动力学完全一致。

更强的学习证据：原四种子 1000 轮模型中，run01/run04 固定左腿，run02/run03 固定右腿。因此固定侧不是当前代码把右腿唯一写死。单侧固定在早期训练 checkpoint 中已经出现，早于这次加速度预算实验。

详见 mechanics-agent/report.md、cross-seed-results.json，以及相邻 right-leg-saturation-lineage-20261013-v1/report.md。

### 2. 饱和的是策略可执行动作，不是机械关节撞限位

85% 候选在停车时右腿 raw mean 约 -4.56/-4.90，执行 clip 后长期都是 -1。相同的 -1/-1 目标主要让虚拟腿整体转约 20°，并非到机械限位。

当前 PPO 对“raw Gaussian 动作 + 环境 clip”的 log probability 用法是合法的，不是算错概率。问题在于大量不同 raw 值会变成同一个电机目标，且执行动作平滑成本在固定通道上接近零。Gaussian entropy 也不等于真实电机动作的探索程度。这是饱和模式得以维持的合理机制，不能据此声称已找回当年唯一的训练梯度原因。

当前左腿前后电机实际角相关系数约 0.957，实际角加速度能量约 94.7% 属于两电机同向的虚拟腿整体转动。只限制腿长变化不能直接处理这个主模态；直接锁死 phi0 则会拿掉姿态调整能力。

相关生产代码边界：
- wheelleg_dreamwaq/source/wheelleg_dreamwaq/wheelleg_dreamwaq/algorithms/dreamwaq/ppo.py:162 保存 raw action，:164 保存其 raw Gaussian log probability。
- 同目录 actor_critic.py:232 重算相同 raw 动作概率，:236 的 CENet decoder 当前使用 raw 的 clip。
- tasks/direct/wheelleg_flat/rewards.py:67 的 action_smooth 汇总六维执行动作。

### 3. 六维总平滑代价与实际左腿抖动并不等价

已有停车轨迹中，六维 action_smooth 的约 99.66% 来自两轮。旧四腿加速度预算又取自已经单侧固定的参考：右侧预算特别小，共同自适应 gain 很早就到上限，归一化超额主要由右侧贡献。

这解释了为什么“总惩罚变大”并未自动对准左腿的抽动。目标不变的腿也会被轮子/身体耦合带动，不能把指令平滑等同机械静止。

### A. 电机目标做明确的一阶时间过渡

控制步长仍为 0.02 s：

```text
applied[t] = applied[t-1] + alpha * (clip(raw[t], -1, 1) - applied[t-1])
alpha = 1 - exp(-2*pi*fc*0.02)
四腿 fc = 6 Hz，alpha ≈ 0.52951
两轮 fc = 2 Hz，alpha ≈ 0.22223
```

这里 fc 是时间常数的参数标签，不应冒充离散系统精确的 -3dB 截止点，更不是只允许机器人以 6 Hz/2 Hz 动作。它使跳变目标逐步过渡，低频姿态调整和轮速目标仍可改变；附加滞后必须通过换向测试评估。

传感器、五帧 history 和 CENet 完整保留。previous action 记录的是真实 processed action。腿位置比例、名义角、原 PD、轮速度比例、真实力矩限制、接触和物理参数全部沿用原控制器。没有加入人工角速度限速力矩。

### B. 只在持续零速度命令时做很慢的小纠偏

只使用可观测信号：两轮编码器平均转速×半径 0.0625 m，和控制坐标下 IMU yaw 角速度。两信号先用 1 Hz 一阶低通。

当原始 vx/yaw 命令都严格为零，且完整原始三维命令保持不变至少 0.5 s，才更新慢积分纠偏：

```text
I += 0.3 * (原始目标速度 - 滤波后的测量速度) * 0.02
vx、yaw 两通道 I 各限制在 ±0.06（各自单位 m/s、rad/s）
策略所见命令 = 原始命令 + I
```

不使用比例项。原始命令切换或非零时纠偏输出为零、积分状态冻结；每次 reset 时动作滤波状态、传感器滤波状态、积分器和计时状态都清零。动作/观测历史遵守实际顺序：只刷新当前帧的策略命令，前四帧保留真实旧命令和 processed action。

所有验收误差均对照**原始用户命令**，没有用修改后的策略命令把误差变小。控制器不使用 MuJoCo 真实机身速度；真实速度仅用于记录/计算误差。

这个补充很关键：单独 6/2 滤波虽能减抖，但长时间停车漂移反而更大。全时 PI 或零命令即刻开启的纠偏又破坏了部分停车换向；0.5 s 门控慢积分才在本轮测试中同时保留换向与停车改善。

## 结果：实际腿运动与速度跟踪同时测量

所有静态场景 10 s；表格排除前 2 s，MAE 为平均绝对误差。表格均比较同一个 85% actor 与原 PhysicsV5。

| 场景/指标 | 原策略直接执行 | 候选方案 |
|---|---:|---:|
| 标准停车，vx MAE (m/s) | 0.0294 | 0.0147 |
| 标准停车，yaw MAE (rad/s) | 0.1270 | 0.0283 |
| 前进 +1 m/s，vx MAE (m/s) | 0.0250 | 0.0277 |
| 后退 -1 m/s，vx MAE (m/s) | 0.0469 | 0.0644 |
| 左转，yaw MAE (rad/s) | 0.1544 | 0.0786 |
| 右转，yaw MAE (rad/s) | 0.1632 | 0.0646 |
| 标准停车，左前电机实际 1ms 角加速度 RMS (rad/s²) | 32.1105 | 1.9566 |
| 标准停车，左后电机实际 1ms 角加速度 RMS (rad/s²) | 30.5282 | 5.0283 |

左腿两电机合成角加速度 RMS（两项平方和开根号）下降 **87.82%**。1ms 实际角 p5–p95 跨度从左前/后 1.93°/2.24° 降至 0.70°/1.02°；因此既有真实减抖，也有残余动作。这里比较的是实际电机运动，不是 raw action 曲线是否变好看。

四组原有停车换向判据全部通过。最差停车 vx MAE 0.09458 m/s，门槛 0.10；最差 yaw MAE 0.10116 rad/s，门槛 0.15；阶段 2/4 最慢换向持续入带确认 0.62 s，门槛 1.0 s。停车速度余量有限，不应宣称任意场景都有充足余量。原判据阶段 0 仅要求完成，不约束首次响应时间。

八个既有静态场景完成且未触发跌倒/高度/闭环失败；这不等于正式架构全部验收通过。左右 phi0 差 RMS 仍约 23.4°–34.0°，高姿态高度误差也仍存在。

### 长时间停车：不能只看净位移

60 s 指令一直为零，下表统计 2–60 s，同样初态和物理模型：

| 指标 | 原直接执行 | 仅 6/2 滤波 | 滤波 + 停车慢纠偏 |
|---|---:|---:|---:|
| 最终净位移 (m) | 1.348 | 1.810 | 0.0380 |
| 最大离开统计起点距离 (m) | 1.348 | 1.810 | 0.0595 |
| 累计移动路径长度 (m) | 1.829 | 2.286 | 1.051 |

候选确实不再持续漂移一两米，且不是走远了最后偶然返回：最大偏离约 6 cm。但累计路径仍 1.05 m，说明在小范围内往返，不能说原地纹丝不动；也没有位置目标或位置反馈。

### 独立命令与外推

参数冻结后，另用 seed=637415 的 20 段新运动/停车/高度命令，长度 74.14 s。候选 vs 同样滤波但不纠偏：
- vx MAE 0.08274 vs 0.09357 m/s；
- yaw MAE 0.06195 vs 0.06534 rad/s；
- 都完成，没有跌倒，候选最大倾斜约 7.01°。

向前/后/左/右分别施加 10 N、20 N，持续 0.16 s，作用在原 base COM，无附加外力矩；共八个候选与八个滤波对照，都完成 15 s。20 N 前推时，候选最大倾斜约 16.67°，最后净位移仍约 0.667 m。这证明在这些明确扰动下没有失稳，不证明推后回原位置，也不证明未知更强扰动。

另外，冻结慢纠偏之前的 12 个新静态运动命令验证的是**滤波方案**，不是独立验证完整停车纠偏；不要把这些重复算作最终候选的新训练种子。

## 已排除/不推荐的替代做法

- 删除/冻结轮动作历史可以降左腿加速度，但会损坏速度/轮子行为；本方案完整保留反馈。
- 将 CENet 估速换成 MuJoCo 真实速度仍不能让全部停车换向通过；这也不是可部署输入。
- 左右镜像双推理平均并没有修复姿态：多个分支很快失败或速度误差显著增大。不强迫左右腿动作相等。
- 腿和轮统一 2/3/4 Hz 会改善静态曲线，却破坏部分换向。不当成 6/2 的等价替代。
- 全时慢 PI、零命令无等待立即纠偏也破坏部分练习。不能只拿停车数据挑纠偏。
- 仅调大共同 smooth/旧自适应 gain 没有得到同时控制抖动与速度的证据。

verify_frozen_candidate.py 不运行 rollout。它独立检查：

- 所有 history 前四帧连续性、真实 previous processed action、真实关节速度/位置；

- 每帧传感器低通、完整命令稳定计时、门控积分器、策略命令与用户命令的区别；

## 下一步方案与本轮的停止点

先按固定候选做 MuJoCo 可视化确认，同时显示原始命令、实际速度、raw/processed 六维动作和四个真实电机角。重点确认减抖是否达到用户肉眼需求，以及剩余停车小范围往返/左右倾斜是否可以接受。不要只凭角加速度降低就宣布“腿不震荡”已经完成。

若将候选转为正式功能，应先写独立具名的架构合同，再实施训练/推理一致的路径：
1. 动作滤波公式、六维状态、实际 previous action、reset 与控制时序在 Isaac、play、export、MuJoCo、部署端完全一致。原普通 PPO 和旧模型必须保持旧合同与原件。
2. PPO storage 继续保存 raw action 和对应 raw log probability；CENet decoder 必须使用实际 processed action。当前 actor_critic.py:236 的 raw.clamp 在现有未滤波训练中正确，未来滤波后不能继续冒充真实执行动作。
3. 若把停车纠偏也纳入训练，需要明确原始命令与策略命令分别用于什么观测/奖励，积分器、测量滤波器和 0.5s 计时的可观测性、reset/resume/export 状态。不能在 MuJoCo 偷加后把它说成训练策略的能力。当前停车纠偏先保持为 debug 中独立可见的控制层，尚未设计正式训练契约。
4. 再开展获授权的新训练对照，分开记录腿/轮动作代价、每腿实际高频运动、动作饱和、跟踪和停车。避免将已经固定一侧的旧数据当安全预算；bounded distribution/超界 raw 惩罚是另一项独立学习设计，不与第一轮无条件捆绑。

当前已经追清执行映射、几何主模态、固定侧的 checkpoint/种子关系，以及保留反馈的减抖控制路径。尚未保存的早期 Isaac 状态/优势/逐电机梯度无法从旧 checkpoint 恢复，所以不能靠继续读取文件确定唯一训练因果；不训练也不能证明某个奖励或概率分布改法重训后必然成功。

本轮得到的是**可复现、同时明显减抖与保留跟踪的候选 + 明确剩余问题及正式实施边界**，不是将所有控制问题都宣布修好。串行复核文件在 final-conclusion-review 下补充记录。
