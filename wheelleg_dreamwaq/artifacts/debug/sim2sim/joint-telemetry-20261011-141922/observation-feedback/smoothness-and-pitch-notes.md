# 左腿平滑奖励与 pitch/phi0 补充诊断

2026-10-11。仅分析原始键盘日志与实际训练 TensorBoard 数据。未修改正式代码、奖励、策略、模型或物理参数，未启动训练。

## 平滑奖励是否起作用

实际 run-03 初训和续训的 TensorBoard 中，Reward/action_smooth 和 Reward/action_rate 均有持续非零负值。续训 iteration 1400 的 action_smooth 为 -0.0014480766，action_rate 为 -0.0005713523；这些是训练环境六个动作的汇总量，不是左腿专属日志。数据保存在 smoothness-training-events.json。

源码 rewards.py 的 action_smooth 衡量裁剪后的归一化动作二阶差分平方；env.py 在每个控制步先更新前两帧动作，再写入本帧动作。左腿动作属于六维求和范围。此项不直接测量实际关节抖动，也不是运行时输出滤波器。

停车 2–10 秒的 400 帧 MuJoCo 记录，按 checkpoint 冻结的训练奖励公式复算：

| 部位 | action_rate / 步 | action_smooth / 步 | 合计 / 步 |
| --- | ---: | ---: | ---: |
| 左腿两个关节 | -0.000003480 | -0.000006885 | -0.000010366 |
| 右腿两个关节 | 0 | 0 | 0 |
| 两个轮子 | -0.000521035 | -0.001068432 | -0.001589466 |

左腿两关节每帧二阶差分均非零；目标角度的 5–95 分位跨度约 5.84 度、4.48 度，相邻目标角度差 RMS 约 2.11 度、1.59 度。左腿 action_smooth 单项约为正向 vx 跟踪奖励的 0.0173%；与 action_rate 合计约为 0.0260%。先前六个动作合计约 4.01%，其中 99.35% 来自轮子。

这说明左腿来回动作符合惩罚公式，但在该轨迹中扣分较轻。此比例只比较该轨迹的平均奖励量级，不代表梯度比例，也不能单独证明起振根因或保证加大奖励权重就能解决。MuJoCo 拆分量是离线复算，不是 Isaac 训练中直接记录的逐腿奖励。

右腿裁剪后的动作在该停车窗口固定为 -1，因此动作平滑项为零，即使原始网络输出仍有变化。实际关节速度/加速度另由 dof_vel、dof_acc 约束；它们也不是硬性禁止振动的条件。

## pitch 与 phi0

pitch 是车身相对地面的倾斜；phi0 是髋轴到轮轴的虚拟腿向量在车身局部平面内的方向，竖直向下约为 90 度。两个量分别描述车身姿态与腿形。

本次轨迹加减速时 pitch 有明显变化，但左腿 phi0 也明显变化。例如 14–16 秒内，其 5–95 分位为 76.54–93.11 度，而右腿为 110.59–110.86 度。停车时左右 phi0 均值分别约 86.32、110.64 度，显示持续不对称。相关图见 pitch-phi0-analysis.png，窗口统计见 pitch-phi0-analysis.json。

正式架构 ADR-004 使用四个腿关节位置目标与两个轮速目标；没有预设“速度指令必须先生成 phi0 目标”的控制链，也没有直接 pitch 动作。phi0_symmetry 仅惩罚左右角差，不设绝对 phi0 目标。因此目前策略可以同时调整轮子、腿形和车身姿态。角度轨迹不能证明两者对整车重心位移的各自因果贡献，不能把本次行为归结为只靠 pitch。
