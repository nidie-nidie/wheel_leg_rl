# run-04 零速站立：Isaac / MuJoCo 同时刻策略边界诊断

日期：2026-10-10。正式架构保持 v0.24。此次只增加独立诊断文件，没有训练，没有修改正式代码、策略、奖励、动作、命令采样、随机化、USD、MuJoCo XML 或仿真参数。

## 结论

同一个 run-04 策略在两个仿真器中均学到了持续后退的稳定行为。稳定阶段 CENet 已能识别后退，Actor 仍持续输出后退轮速目标。因此，当前零速站立问题的调查应优先转向训练策略与奖励取舍，而不是先改变历史窗口或把速度估计当作主要原因。

这是定位方向，不是对奖励根因的最终确认。MuJoCo 比 Isaac 多后退约 0.039 m/s，仍存在迁移差异，但 Isaac 本身已有约 0.459 m/s 的后退，单独修复迁移不足以解释或解决站立目标。

## 离线速度替换

在记录的同一 current observation 和 context_mu 上，把输入 Actor 的估计 vx 替换为同一帧真实 vx，保留其余输入，再回放 Actor。左/右轮目标仍为：

| 只替换真实 vx 的离线输出 | Isaac | MuJoCo |
| --- | ---: | ---: |
| 左轮目标（rad/s） | -8.381388 | -8.963390 |
| 右轮目标（rad/s） | -8.334771 | -8.833915 |

把三维速度一起替换为真实值时，也仍持续输出后退目标。此结果表明，小幅速度估计偏差不足以直接解释当前 Actor 的后退指令。离线回放没有驱动仿真，不代表速度替换后的闭环轨迹或停住能力。

## 诊断有效性与限制

- MuJoCo 新诊断与之前正式 nominal_stand 的 500 帧动作和动作后 vx 完全一致，最大差值均为 0。
- Isaac nominal_stand 回报与此前正式评估完全一致：22.441320539452136。
- 从导出 actor.ts 回放两端记录的输入，动作最大误差不超过 1.91e-6，速度估计最大误差不超过 4.77e-7。CPU 批量回放与原逐帧/GPU 计算的浮点差异在验证容差内。
- history 的推进、前次动作和动作前后速度连续性均逐帧核对。Isaac 最后一次 step 内自动 reset，最后的 reset 后状态明确排除出 post-action 比较；全部结论使用 reset 前数据。
- 首次 Isaac 诊断在最后的自动 reset 状态比较断言处停止；已修正诊断记录器的结束处理并完整重跑成功。失败日志与记录保留在 `isaac-attempt01`，正式 reset 代码未改。
- 101 个正式源文件、架构和输入/旧结果文件的 SHA256 保持不变。
- 结果只针对 run-04、nominal_stand、约 10 秒诊断，不代替完整性能验收，也未验证修改后的站立恢复。

只读核对当前导出 manifest 和 `tasks/direct/wheelleg_flat/commands.py` 可见：站立模式设置为 20%，该模式确实把 vx 和 yaw 命令置为 0 并保持整个 episode。这里是配置概率，不是从训练日志测得的实际样本占比，也不是已确认的充分或不足结论。
