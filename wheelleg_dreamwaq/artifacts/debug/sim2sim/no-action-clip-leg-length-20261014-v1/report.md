# MuJoCo 无动作裁剪与腿长窗口诊断

日期：2026-10-14
状态：debug-only，未启动训练，未修改 Isaac 训练路径。

## 目的

使用同一个 DreamWaQ run-03 导出物，在同一个 MuJoCo 模型、同一个 formal_1ms 时序和同一个命令下，只改变策略动作进入目标计算前是否执行 [-1, +1] 裁剪。

- 基线：正式动作裁剪；历史观测使用 clipped action。
- 诊断：原始动作参与腿目标和轮速目标计算；历史观测仍使用 clipped action。
- 两者都保留目标角限幅、扭矩限幅、现有终止检查。
- 同时记录虚拟腿长是否处于 0.15–0.35 m，以及闭链误差是否超过 5 mm。

## 结论

仅依赖 base_height 不能保证腿构型保持在安全范围内。原始动作目标版本中，机身高度仍在当前 0.10–0.40 m 终止范围内，但虚拟腿长已经多次低于 0.15 m。

因此：

1. 0.15–0.35 m 可以作为 debug 诊断窗口；
2. 不能据此直接删除目标角限幅并开始训练；
3. 当前无动作裁剪诊断已经证明策略原始输出会显著放大腿目标和轮速目标；
4. 下一步应先决定是否把腿长窗口升级为明确的闭链安全终止/约束，再讨论训练版动作合同；
5. 本次结果不证明无裁剪训练一定失败，因为现有 checkpoint 是在 clipped action 合同下训练的；它只证明把旧策略直接接到无裁剪目标上会越过腿长窗口。
