# 左右轮差速来源追查（2026-10-16）

## 结论

当前训练中没有一个奖励项直接惩罚“左轮和右轮的目标速度差”或“左轮和右轮的实际速度差”。因此，策略可以在身体前进速度和偏航速度基本满足的情况下，保留一个左右不同的轮动作。

在零偏航、零速度指令的 MuJoCo reset 状态，当前去掉动作裁剪的策略第一步就输出：

- 左轮动作：`0.865081`
- 右轮动作：`0.564031`
- 差值：`0.301051`

此时当前帧观测中的腿位置误差约为零，六个关节速度也约为零，偏航指令为零。差速动作先由策略网络产生，随后才造成轮速和机体偏航变化。

## 奖励逐项追踪

正式奖励定义位于 `source/wheelleg_dreamwaq/wheelleg_dreamwaq/tasks/direct/wheelleg_flat/rewards.py`。

### 速度跟踪奖励

`tracking_vx` 只使用机体根部线速度的 `x` 分量，`tracking_yaw_rate` 只使用机体根部 `z` 轴角速度。它们评价最终身体运动，不评价左右轮如何分配目标速度。

当偏航速度误差为 `0.06 rad/s` 时，当前 `tracking_sigma=0.25` 和 `control_dt=0.02` 产生的单步主偏航跟踪损失约为 `0.000286`；宽范围增强项的单步损失约为 `0.000029`。这个信号可以惩罚结果偏航，但无法告诉策略“应该把左右轮动作收敛到相同值”。

### 关节速度奖励

当前代码是：

```python
torch.sum(torch.square(state.joint_velocity[:, :4]), dim=-1)
```

它只包含四个腿关节，两个轮关节被明确排除。轮子持续高速或左右轮持续不同速，不会通过 `dof_vel` 受到惩罚。

### 动作变化奖励

`action_rate` 使用相邻动作差，`action_smooth` 使用二阶动作差。两项都约束动作随时间的变化。

如果策略从初始动作过渡到左右不同的轮动作，然后保持这个差值，后续时间步的这两项不会继续因为“左右不同”增加惩罚。它们可以抑制轮动作来回变化，无法约束稳定存在的左右差速。

### 力矩奖励

`torques` 包含六个执行器，但权重只有 `-1.0e-4`。它会轻微抑制大力矩，缺少针对左右轮力矩差的结构。

### 腿对称奖励

`phi0_symmetry` 只计算左右虚拟腿 `phi0` 的差异，与轮速目标、轮关节速度和轮端力矩没有直接关系。它无法约束左右轮差速。

## 为什么策略会保留差速

当前奖励对身体速度跟踪有明确收益，对轮端差速只有很弱的间接代价：

1. `tracking_vx` 鼓励策略产生能够推动身体前进的轮动作；
2. `tracking_yaw_rate` 只在产生实际偏航后惩罚结果；
3. `dof_vel` 没有轮子项；
4. `action_rate` 和 `action_smooth` 不惩罚稳定的常值差速；
5. `phi0_symmetry` 只看腿的几何对称；
6. CENet 的辅助损失重建本体观测和根部线速度，没有左右轮差速目标。

因此，当前策略学到的是“能完成身体速度任务的六维动作”，奖励没有要求它使用左右相同的轮动作来完成零偏航前进。

## 随机化对这个结果的影响

随机化为六个受控关节分别采样 `kp`、`kd` 和力矩上限，两个轮子的参数也独立采样。轮摩擦在每个环境中按一个轮子材料值设置，左右轮共享该环境的摩擦值；执行器增益和力矩上限仍按六个关节分别采样。

这会让训练策略经历左右轮响应不同的环境。由于奖励没有轮端对称项，策略有理由保留左右不同的动作来适应训练环境。MuJoCo 当前使用名义相同的左右轮参数时，网络首步仍然输出差速，说明差速模式已经写入策略输出层，并非 MuJoCo 接触之后才产生。

## 当前能确定的训练指标

造成这个现象的核心训练契约是：

> 身体速度跟踪有奖励，轮端持续差速没有直接代价。

其中最关键的代码事实是 `dof_vel` 排除轮关节，`action_rate` 与 `action_smooth` 只计算时间差分，奖励定义中完全没有 wheel-pair symmetry 或 wheel-speed-difference 项。

这已经足以解释为什么网络会输出不同的左右轮速目标。CENet 估速误差只造成很小的间接影响，当前证据不支持把它作为主因。

## 下一步实验边界

下一步若要调整训练，只需要新增一个条件化的轮端差速代价：在 `command_yaw_rate` 接近零时惩罚左右轮目标差，在有明确偏航指令时降低或关闭这项代价。这样可以保留正常转向所需的差速能力。

这个实验应继续保持去掉六维动作裁剪、CENet、history、执行器力矩、轮子接触和 MuJoCo 参数不变，先单独验证训练指标的作用。
